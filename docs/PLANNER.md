## 2026-10-30：免费本地规则引擎升级

本轮实现、问题优先级和验证边界见 [算法审查与升级记录](PLANNER_ALGORITHM_REVIEW.md)。

- 中英文（含繁体）自然语言入口 `PlannerEngine.advise(task:...)`，独立识别任务类别、复杂度、不确定性、敏感风险和紧急信号。英文按词匹配，避免 `build` 命中 `ui`、`author` 命中 `auth`；修复任务附带测试不会被改判为纯测试任务。
- 高复杂度、高风险或高不确定性统一要求至少 `high` effort；效率、紧急和额度压力不自动降低底线。只在当前目录支持的档位中选择，未知 effort 仅可手动确认。
- 主推荐和最多两个替代配置共用确定性排序：复杂任务的轻量角色惩罚、同类负面反馈、角色适配、推理档位距离、目录核验、默认标记和稳定 ID。没有能力基准时角色仅是启发式；fallback 明示并降低置信度。
- 额度结构统一校验百分比、窗口唯一性、周期及接收新鲜度。输出“配置建议 / 等待 / 需补充信息 / 无合适配置”，保留后余量取两个窗口的最小值，不视为任务预算。引擎保留量归一化到 0–100%，界面继续提供 0–50% 调整。
- 置信度仅为低/中的定性证据强度；未校准前不输出高置信度或成功概率。空白描述不产生配置；陈旧/缺失额度仍可查看条件配置，但状态明确要求刷新。
- 至少五条同任务特征、配置及账户范围的有效用户填报后，展示 Token 中位数和观测最小–最大范围。排除重复 UUID、未来/倒置时间及跨来源反馈。范围不是预测区间，不换算订阅额度，也不归因单任务账户消耗。
- 仍然无需 AI API、联网推理、额外依赖或模型名单。任务只在内存分析，原有历史 schema 与保存偏好兼容；可选保存短标题的行为不变。

## 已实现

- 主窗口可自由调整尺寸，最小 760 × 620pt；预览按可用宽度分页，不改变桌面面板尺寸。1080pt 以上可并排显示 300pt 玻璃设置；窄窗口使用设置弹窗，避免 Inspector 将两侧挤出。
- “额度与面板 / Planner”工作区。现有面板、玻璃参数、时钟和额度连接不变。
- 3.0：本地关键词分类，每次生成按当前文本重新识别；手动类别/规模/不确定性/风险覆盖独立保留。支持质量/平衡/效率偏好，动态模型目录、合法 effort 组合、理由、替代项和手动覆盖。草稿保存在本窗口内存中，切换工作区不丢失，关闭窗口不落盘。
- 3.1：复用现有来源，同时检查独立的 5h 与周额度，显示接收时间、来源、过期/重置状态与每窗口保留量。低于保留量建议等待；不因额度不足而把高风险任务偷偷降为低档。
- 3.2：保存计划、标记开始、记录完成/部分完成/失败/未评估；支持质量反馈、重试、返工、验证结果与可选的用户填报 Token。任务历史可逐条删除或清空。
- 相同任务特征、模型、effort 和已知范围至少有 5 条人工反馈后，失败/返工较多的配置降序；样本数及完成数明确展示，不称为已验证的成功概率。用户填报 Token 中位数和订阅百分比独立显示。

## 数据流与文件

`model/list → CodexAppServer → QuotaMonitor → PlannerView`

`PlannerProfile / PlannerEngine → 配置建议 → PlannerStore → PlannerPersistence`

- `Shared/Planner.swift`：目录解析、分类、额度状态、推荐规则、记录与版本化持久化。
- `App/PlannerStore.swift`：异步本地文件访问与任务生命周期；重启后的“进行中”标为中断待确认。
- `App/PlannerView.swift`：原生输入、理由、覆盖、反馈与历史。原始输入只在界面内存中处理。
- `~/Library/Application Support/CodexQuota/planner-history.json`：沿用旧数据目录，不含邮箱、登录凭据或项目内容。账户/会话范围只保存哈希或来源提供的会话指纹。文件权限 0600，不是加密。
- 默认不保存任务描述/背景。用户主动勾选后仅保存最多 120 字的任务短标题。
- Schema 1；缺省版本 0 可读并在下一次保存升级。损坏或未来版本默认拒绝写入、保留原件；仅明确清空时重置。最多 500 条、2 MiB，不静默丢弃旧记录。

## 模型与外部接口边界

本机 Codex CLI `0.164.0-alpha.11.1` 生成的 schema 已核对；目录按返回的 `model`、`displayName`、`defaultReasoningEffort`、`supportedReasoningEfforts`、`isDefault`、`hidden`、`nextCursor` 处理。目录支持分页，循环 cursor、重复模型和超限响应被拒绝。超时不影响额度刷新。

官方接口说明：[App Server / List models](https://learn.chatgpt.com/docs/app-server)。`model/list` 是目录，不是完成一次推理的授权证明；不同客户端配置可能返回内置目录，见 [Codex app-server](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server)。本实现没有付费推理“验权”。

- 不写死模型名单。模型角色只根据目录描述的关键词或用户手工声明作启发式判断，不是性能/成本基准。
- 目录有效期 30 分钟；Codex 额度保鲜 120 秒、Claude 被动记录 300 秒。缺失任一支持窗口均单独提示未知；手动目录标为未核验，仅本窗口会话生效。同名实时目录恢复后优先使用实时条目，不产生重复选择项。
- 当前目录没有经过核实的单模型额度价格/成功率/上下文上限，不补造。不能承诺推荐模型一定更省订阅额度。
- Claude 仍为实验性 statusLine 接入，尚无动态模型目录；只有用户确认过的手动配置可以参与建议。
- 复制配置只复制模型 ID 与 effort，不含任务正文。不会操纵官方 Codex Desktop 的模型选择器、启动任务、修改 `config.toml` 或用户项目。

## 不做虚假归因或预测

起止额度不必全来自该任务，可能受其他设备、会话、延迟和共享池影响。即使百分比只下降且重置点相同，也只标为“期间账户变化”。重置、窗口变更、范围切换与过期记录分别提示。当前没有可信的隔离任务资源流，因此**不学习精确额度成本，不预测还可完成多少任务，不把百分比换算成 Token**。

人工质量反馈可用于保守降序；它不证明模型因果性能。历史不足时规则建议仍可用，估计保持未知。

## 3.3 的安全扩展点

推荐引擎不依赖 SwiftUI 或执行接口，未来可把配置作为一段任务建议。只有官方接口可验证有效配置、上下文迁移与权限时，才另增用户发起的执行适配层。当前没有多阶段自动路由或自动切模；没有后台执行权限。
