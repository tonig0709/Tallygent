# 逐时额度追踪 — 大型面板图表

Tallygent 的逐时额度追踪将 Insights 的历史带到大型桌面面板，现已随 [v0.7.1 / build 52](https://github.com/tonig0709/Tallygent/releases/tag/v0.7.1) 正式发布。首个本地测试是 build 51；正式包与其运行时代码相同，仅递增发行元数据并更新说明。请从 [Releases](https://github.com/tonig0709/Tallygent/releases/latest) 下载实际公开的 DMG。

既有 v0.7.0 / build 50 标签、安装包及草稿保持不变，粒子实验也不混入此次更新。

## 设置入口

在 App 的「玻璃设置」或桌面面板边缘设置弹窗中，找到「大型面板图表」：

- 图表内容：近 7 天 Token、过去 12 小时额度、过去 24 小时额度。
- 图形样式：柱状图或折线图，两类数据均可使用。

默认仍是现有七日 Token 柱状图。选择立即同步到 App 预览与已放置的同一个桌面面板，并在重启后保留。小型、中型面板以及玻璃参数和底层渲染不受影响。

## 坐标轴标注（后续本地 build 53）

- 12h / 24h：横轴标明本地时间，刻度包含时、分；纵轴直接显示 `0% / 50% / 100%`，表示剩余额度。
- 七日 Token：横轴为日期（月/日）；`M` 明确写为“百万 Token”，不把额度比例换算成 Token。
- Insights 使用同一百分比格式；跨日期的历史刻度同时显示日期与时间，避免不同日期的相同时刻混淆。
- 首尾时间标签向图内对齐，并使用原生刻度冲突处理，不靠缩小字号或截成省略号来隐藏时间。
- 这是标注更新，不改变面板尺寸、玻璃渲染、历史采集或刷新机制；尚不包含在已发布的 build 52 中。

## 数据含义

12h / 24h 与 Insights 一样展示 **剩余额度百分比**，5h 和周额度各占一个小图。它们不是小时 Token 数，也不是推算的消耗量。

- 折线使用真实观测点并保留连续区段，重置、身份切换、缺失与长间隔不连线；孤立观测显示为点。
- 柱状图取每个钟点小时内最后一次有效观测的剩余百分比。没有观测的小时留空，不补零、不推算。
- 历史从启用采集后开始，沿用既有有界读取上限；选择 24h 不等于已经拥有完整 24h 数据。
- 旧记录仍可作为历史显示，但会标注「旧记录 · 待更新」。当前身份未知，或历史不属于当前账户／绑定会话时，不展示其他身份的历史。

## 同步与隔离

仍由既有 InsightsStore 和单次 SQLite 读取提供数据，不新增账户连接或轮询。读取范围至少包含 24h，Insights 页选「近 1 小时」不会截断面板；清空历史会同步清空面板历史。

预览和桌面面板直接观察同一个历史 Store。图表时间域锚定最近一次历史读取时间，避免拖动玻璃滑杆时不断重建曲线；右上角系统时钟继续独立逐秒运行，不能被当作新数据。

现有链路已经自动读写：Codex 约每 15 秒请求额度，也响应来源通知；有效响应写入观测库后立即重新读取并更新曲线。Claude 由被动桥接事件写入，App 定期读取且历史读取有 15 秒节流；并不主动每秒查询 Claude 服务器。暂停采集后不会为保持动画而补造历史。

柱线样式和内容分别保存在 `desktopPanelChartStyle`、`desktopPanelChartSource`；未知值安全回退到七日 Token 柱状图。修改图表设置不写入新的额度观测。

## 回归

`scripts/check-panel-trend.sh` 检查坐标单位与百分比缩放、时间边界、账户／会话隔离、分段、采样、小时末次观测、DST、Insights 范围独立、读取失败和清除。它只使用临时数据。

完整门禁仍须在隔离 CI 用户执行，保留既有三尺寸、单面板、非黑屏、同步、内部布局、签名和 DMG 一致性检查。原生桌面的实际拖动、悬停及连续滑杆仍需人工确认，自动化不冒充真人操作。
